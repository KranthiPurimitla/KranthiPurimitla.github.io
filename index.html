Engineering projects

I develop Python and YAML integrations on Dynatrace Extension 2.0. These projects cover the path from collecting a signal on ActiveGate to using it in a dashboard or an alert.

NetApp storage alerts from SNMP trapsStorage monitoring
Challenge
A storage device could report a nearly full volume, but an isolated trap gave responders little context about which volume needed attention.
Architecture
NetApp EMS sends SNMP traps to an ActiveGate receiver. OpenPipeline extracts event fields, and Dynatrace uses them to create Davis events.
My implementation
I configured extraction and routing, investigated how events attached to entities, and added separate checks for offline volumes, utilization and selected hardware conditions.
Operational value
Storage teams can search the events in Dynatrace and use volume-level alerts to investigate capacity and availability issues.

Extension 2.0 · SNMP · ActiveGate · OpenPipeline · DQL

Genesys Cloud conversation analyticsContact-center telemetry
Challenge
Operations needed to compare conversations offered and connected across queues. The detail API returns results through an asynchronous job.
Architecture
A Python Extension 2.0 collector authenticates to Genesys Cloud with OAuth, submits an analytics job and polls for completion.
My implementation
I implemented cursor-based result collection and mapped conversation counts and timings to metrics with queue, media type and direction dimensions.
Operational value
Teams can compare queue activity in Dynatrace and investigate differences between offered and connected conversations alongside other service telemetry.

Extension 2.0 · Python · REST · OAuth 2.0

Pure1 volume capacity monitoringStorage analytics
Challenge
Provisioned capacity and physical usage came from different Pure1 endpoints, making it difficult to compare volumes consistently.
Architecture
A Python collector exchanges an RSA-signed JWT for an OAuth token. The signing key is retrieved from Dynatrace Credential Vault.
My implementation
I collected provisioned volume metadata and physical-capacity history at a supported resolution, then used DQL to calculate physical usage as a percentage of provisioned capacity.
Operational value
Storage engineers can sort volumes by percentage used and identify which volumes merit a closer look.

Pure1 REST API · Python · JWT · Credential Vault · DQL

VeloCloud SD-WAN link healthNetwork observability
Challenge
Network teams needed to see which edge and link a performance signal belonged to when investigating an SD-WAN issue.
Architecture
A Python-based Dynatrace Extension 2.0 integration reads edge and link telemetry from the VeloCloud REST API.
My implementation
I developed the collection logic and monitoring configuration, then modeled edge and link dimensions so teams could compare individual connections.
Operational value
Network teams can review link-level metrics in Dynatrace alongside the application signals they are investigating.

VMware VeloCloud · Extension 2.0 · Python · REST

CyberArk credential retrievalPlatform integration
Challenge
Authenticated monitoring could fail when a vault lookup matched no account or returned several possible accounts.
Architecture
Dynatrace Credential Vault requests account secrets from CyberArk for authenticated monitoring integrations.
My implementation
I traced lookup parameters across both systems, identified a case-sensitive mismatch, and worked with the identity team to distinguish missing matches from ambiguous account searches.
Operational value
The investigation isolated the cause of failed secret retrieval and gave the teams a specific account-matching condition to validate for rotation.

CyberArk · Dynatrace Credential Vault · Authentication

Synthetic monitoring and alert refinementAlert quality
Challenge
Broad matching conditions caused synthetic failures outside the intended scope to trigger notifications.
Architecture
HTTP synthetic monitors feed Dynatrace alerting profiles. Tags, management zones and outage filters determine which events are routed.
My implementation
I configured the monitors and narrowed the profile to require all relevant tags, the intended management zone and the appropriate outage condition.
Operational value
The revised configuration targets the failures the team intended to investigate and supports reviewing the routing before enabling notifications.

Dynatrace Synthetic · Tags · Management zones · Alerting profiles
